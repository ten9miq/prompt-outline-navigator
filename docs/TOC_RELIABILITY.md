## 維持する判定規則

| 状態 | 目次・移動の扱い |
| --- | --- |
| 表示中の明示的な会話ルート | 最優先。非表示の旧ルートを含む祖先スクローラーで置き換えない |
| 会話ルートの印がないが会話用スクローラーと明示的なメッセージ本文がある | 限定したfallbackで検出する。一般の`main`全体から見出しを推測しない |
| 入力・役割属性・IDが遅れて描画される | 回答の検出とラベル確定を分ける。新しく認識した入力へ訂正し、同じ入力IDのラベルは維持する |
| HTML見出し、ARIA見出し、リッチエディタ、生Markdown | 共通のoutline targetとして扱う。生Markdownの移動先はRangeで測定し、本文を改変しない |
| 文書自身の展開ボタンに結び付いた折りたたみ本文 | 項目を残す。展開要求と本文の非表示解除は別状態とし、再描画後に移動する |
| 非表示の別回答・プレビュー・入力欄・ダイアログ内のフィード | 混入させない。`inert`だけで読み取り可能な本文を消したとは扱わない |
| 過去ターンがDOMから外れる、同一会話のルートが置き換わる | 安定キーのある過去項目と全体順序を保持する |
| 同じ接続中の単一回答位置で回答IDが置き換わる | 再生成として旧項目を除去する。複数の可視回答を一つに集約しない |
| 新しい会話へ切り替わる | 前の項目・保留中の移動・更新要求を持ち越さない |
| 本文だけのトークン追加 | 見出しを再生成しない。エディタ変更は影響した回答へまとめて適用する |

包含判定は`isTocContent`、折りたたみ領域の所有は`getWritingBlockRegion`、移動前の待機は`getWritingBlockDisclosure`を使います。個別の呼び出し元で異なる非表示判定を追加する前に、これらと整合させてください。

表示件数だけでなく、所属するPROMPT、ラベル、重複、順序、移動先、元の本文の維持を確認します。実際に見出しを削除した場合には目次からも削除されることを確認し、単純に古い項目を残して不具合を隠しません。

```powershell
npm run check
npm test
git diff --check
```

Playwright用ブラウザーの保存先を指定する環境では、インストール時と実行時に同じ`PLAYWRIGHT_BROWSERS_PATH`を使います。特定の状態遷移だけを再検証する場合は`npx playwright test tests/toc-lifecycle.spec.js --workers=2`を使用できます。

## 確認済みの範囲と限界

この見直しでは単体90件、ブラウザー41件が成功しました。通常会話と、部分修正を含むプロジェクト会話は専用Chromeで目次を確認し、旧文書の展開・見出しへの移動・移動後の位置維持も確認しました。部分修正の会話は元文書11件・修正版17件を保持しています。

仮想化・遅延属性・回答再生成などの全状態を実サービスに投稿して再現したわけではありません。これらは匿名fixtureでの検証です。ChatGPTの将来のDOM変更や、識別情報も本文も描画されない形式まで保証するものではありません。不具合が出た場合は実DOMの構造だけを匿名化して状態遷移テストへ加え、修正前に失敗し修正後に成功する条件を残してください。
